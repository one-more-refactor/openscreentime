The four on-device surfaces of the Rust/egui client, drawn in the real ring language. The same ring that shows a child their day is the ring that fills full and closes when it runs out — enforcement is the gauge completed, not an alarm raised.

1 · App window — ost app

420×520. The ring is the hero: it fills clockwise from 12 o'clock proportional to the day used — green, then amber under 15 minutes, red at zero. One green action; the honest promise always in view.

2 · Wind-down — the save-your-work countdown

The amber bridge before a stop. A full amber ring; the number counts the grace seconds down. The one motion in the whole client's stop path: amber → red as it reaches zero, the ring hardening into the lock below — no shake, no siren.

3 · Hard-stop lock — lockout.rs

Every reason shares the ring, drawn full and closed. The stop is red for the three walls (time's up, offline, tamper); the expected pauses stay calm — a night ring and a moon for bedtime, the language's own dashed paused ring for a parent pause. Headline and detail are passed verbatim from the runner, so the lock, the tray and the docs never drift.

4 · The way back — challenge & parent code

A present parent can always get in with the unlock code (masked, Space Mono). A self-serve maths challenge buys a short breather. A rejected code does one calm thing: the ring flashes red once and a plain line explains — never a shake.

5 · First-run intro — intro.rs

560×380. The child's documentation as a few honest cards — and the ring is the progress bar: it fills one segment per card, so you fill the ring as you learn how the ring works.

6 · Tray & notifications — voice, not paint

The tray is system-rendered, so the redesign here is the words: every ALL-CAPS mono-console string becomes sentence case, calm and kind. Notifications shown as the desktop would draw them.
